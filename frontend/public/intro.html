Background

项目背景

热搜榜是中文互联网最直观的舆情风向标——但"看见榜单"和"理解榜单"之间隔着采集、清洗、分析、呈现整整一条链路。

这个项目最初只有一个用 Streamlit 快速搭起来的小爬虫：能抓数据、能画图，但每一步都要人手动触发——爬一次、跑一次分析、刷一次页面。在持续迭代中它经历了三次架构演进，最终成为一个真正的"监控系统"：

阶段一 · Streamlit 原型

爬虫 + 分析 + 界面一体的快速验证，跑通了微博接口反爬、数据存储和基础分析，但界面不可定制、无法响应新数据。

阶段二 · 前后端分离（Vue3 + 独立分析）

用 Vue3 按设计稿重构界面，分析模块模块化拆分；但前端与后端尚未打通，数据存在"两张皮"问题。

阶段三 · 一体化实时架构（现在）

引入 FastAPI 作为唯一数据出口：服务内置自动监控线程，定时爬取 → 自动分析 → 前端每分钟拉取最新结果。删除了所有冗余界面与死代码，只保留一个入口、一套界面。

工程上最重要的一课："实时"不是界面好看，而是数据链路的每一环都能自动响应变化——这也是本项目架构设计的出发点。
Core Features

核心功能

五个分析模块 + 一个大模型问答，全部基于真实爬取数据运行，指标均为样本外真实结果。

📡

实时采集与自动监控

UA 轮换、重试退避、请求间隔应对反爬；状态监控记录每次爬取健康度，重启后自动恢复历史统计。

单轮采集 51 条 · 全程零人工干预
requests · threading · 原子写入
🎯

话题生命周期聚类

以峰值热度、持续时长、上榜次数等 17 维特征做 K-Means 聚类，自动归纳爆发型、长尾型等生命周期形态。

轮廓系数自动寻优 K · 无需预设类别数
K-Means · silhouette
📈

热搜排名预测

严格的时间外推任务：只用 t 时刻之前的历史预测下一时刻能否进入 TOP10/TOP5，按时间切分数据集。

TOP10 准确率 92% · AUC 0.967（样本外）
RandomForest / XGBoost · 防标签泄露
💭

情感分析

对话题标题做情感打分与极性占比统计，按小时呈现正面/负面/中性趋势，方法论边界在页面明确标注。

292 个话题全量打分 · 三极性实时占比
SnowNLP · 诚实边界标注
🔍

异常检测

统计法（均值±3σ、排名突变）与孤立森林双路检测，自动识别极高热度、爆款、新晋与消失话题。

7 类异常 · 涉及全部上榜话题
Isolation Forest · IQR / Z-Score
🤖

大模型智能问答

后端代理调用 Qwen，自动把最新榜单 TOP10 与统计信息注入上下文，支持多轮对话与推荐问题。

上下文自动注入 · 未配置密钥时优雅降级
Qwen · Context Injection

Known Limitations

已知局限

主动说清楚系统的边界，比隐藏它更重要——每一条局限都标注了现状与改进方向。

💭 情感分析的对象是标题

SnowNLP 分析的是话题标题文本而非网友评论，反映措辞色彩，不等同于公众情绪；其训练语料为电商评论，对新闻类标题仅供参考。

改进方向：接入评论采集，对真实用户文本做情感建模

📈 预测冷启动期指标偏高

数据积累初期相邻快照排名变化小，预测任务偏简单，指标会虚高；随数据时间跨度增长会回归真实水平。

现状处理：页面展示"预测 vs 实际"对比，不隐藏错误样本

🍪 采集依赖微博接口可用性

热搜接口存在反爬限流，未配置 Cookie 时可能被拦截；微博接口变更需要同步调整解析逻辑。

现状处理：重试退避 + 健康告警 + 失败时保留历史数据不断供
Getting Started

启动方式

两条命令装好依赖，一条命令启动整个系统。

克隆并安装依赖

# 后端依赖（Python 3.10+）
git clone https://github.com/19870034424/weibo-hotsearch-analysis.git
cd weibo-hotsearch-analysis
pip install -r backend/requirements.txt
# 前端依赖
cd frontend && npm install

配置（可选）

不配置也能跑，但建议填入以提高数据成功率与解锁问答：

# 微博 Cookie → backend/config.yaml 的 spider.cookie（降低反爬拦截概率）
# Qwen 密钥 → backend/config/api_keys.yaml 的 api_key（智能问答用）

启动一体化服务

自动爬取（每 15 分钟）→ 自动分析 → API 服务 → 前端托管，一个进程全搞定：

cd backend && python api_server.py
# 打开 http://localhost:8000 即为完整系统

前端开发模式（可选）

cd frontend && npm run dev
# 开发热更新：http://localhost:5173（/api 自动代理到 8000）
提示：服务启动时会立即执行第一轮爬取与分析，所以新环境跑起来几秒内就有数据；之后的采集与分析按配置间隔自动循环。
